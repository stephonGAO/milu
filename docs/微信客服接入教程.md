# 微信客服接入教程（echo 实测版）

把 milu 部署成「微信客服」，让**真实微信用户**能跟你的服务对话。本教程对应
`src/milu/channels/wechat_kf.py` 的 echo 链路——先打通传输（用户发消息 → 原样回显），
确认效果后再把 echo 换成 milu Agent。

---

## 0. 先搞清楚：你到底要接哪个「微信」

| 你想要的 | 合规接入方式 | 本教程是否覆盖 |
|---|---|---|
| **微信用户**（个人微信）能找你的 AI 聊 | **微信客服**（经企业微信）或 公众号 | ✅ 就是这个 |
| 个人微信号直接挂机器人 | ❌ 无官方 API，第三方 hook 易封号，不建议 | — |
| **企业微信内部成员**在企业微信里跟 bot 聊 | 企业微信「自建应用」（另一套收发 API） | ⏳ 可后续再加 |

> 结论：要覆盖「真实微信用户」，合规且能用 API 的路子就是**微信客服**。本教程做这个。
> 企业微信内部自建应用是另一套 `/message/send` + 被动回复 API，需要可单独加一个 channel。

---

## 1. 企业微信侧准备（拿账号和凭证）

### 1.1 注册企业微信 + 实名/认证
1. 打开 <https://work.weixin.qq.com/> 注册企业微信（用微信扫码即可创建组织）。
2. 建议完成**企业认证**（组织主体验证）。部分能力与调用上限需要认证；未认证可先试用基本功能。

### 1.2 开通「微信客服」应用（在企业微信后台，不是 kf 独立后台）
1. 登录**企业微信管理后台** <https://work.weixin.qq.com/wework_admin/>。
2. 顶部菜单「**应用管理**」→ 找到「**微信客服**」（或在「客户联系」分组下）→ 进入。
3. 开启「**API**」能力。⚠️ 后台会要求你**先填好回调配置才能开启**——所以先别急，
   回到本教程**第 2、3 步把服务和公网地址准备好**，再来填回调（见第 4 步）。

### 1.3 创建一个客服账号
- 在微信客服管理界面「**客服账号**」里新建一个账号（名字 + 头像）。
- 创建后会得到一个 **`open_kfid`**（客服账号 ID），以及一个**接待二维码 / 链接**——
  后面测试时用微信扫它进入会话。
- echo 阶段我们的代码会从回调事件里自动拿到 `open_kfid`，**你不用手填**。

### 1.4 记下两项关键凭证位置
- **企业 ID（corpid）**：后台「我的企业 → 企业信息」最下方。
- **微信客服 Secret**：在「微信客服 → API / 开发配置」里。⚠️ **它在你开启 API（第 4 步）之后才能查看/复制**。

## 2. 本地把 echo 服务跑起来

> 在 worktree 目录 `D:\MyWork\milu\milu.worktrees` 下操作。

### 2.1 安装可选依赖
```powershell
# 微信回调的 AES 加解密依赖 cryptography
.venv\Scripts\python -m pip install "cryptography>=3.4"
# 或：pip install -e ".[wechat]"
```

### 2.2 先填「能启动」的 .env（Secret 先占位）
回调验证**只用 Token + AESKey，不用 Secret**；Secret 要等第 4 步开通后才有。
所以先这样填，让服务能启动并通过回调验证：

```ini
# .env（worktree 根目录）
WECHAT_KF_CORP_ID=ww你的企业ID
WECHAT_KF_SECRET=placeholder          # 占位，第 4 步拿到真 Secret 后替换
WECHAT_KF_TOKEN=自己定一串字母数字       # 例：miluKfToken2026
WECHAT_KF_AESKEY=43位的EncodingAESKey   # 见下方说明
WECHAT_KF_CALLBACK_PATH=/wechat/kf/callback
```

- **Token**：随便定一串字母数字（如 `miluKfToken2026`）。
- **AESKey（EncodingAESKey）**：必须是 **43 位** base64 字符（A–Z a–z 0–9）。
  后台「回调配置」里有「**随机生成**」按钮，第 4 步生成后复制过来即可；
  现在想先启动，可临时用 43 个字符占位（如 `abcdefghijklmnopqrstuvwxyz0123456789ABCDEFG`），
  **第 4 步以后台生成值为准、两边保持一致**。

### 2.3 启动
```powershell
.venv\Scripts\python examples\wechat_kf_echo.py
# 监听 0.0.0.0:8800，回调路径 /wechat/kf/callback
```
浏览器或 curl 访问 `http://127.0.0.1:8800/healthz` 返回 `{"ok": true, ...}` 即服务正常。

## 3. 让服务公网可达（HTTPS）——二选一

微信客服回调**必须公网可达 + HTTPS**。两条路：

### 路 A：内网穿透（最快，适合先测效果）
以 **cpolar**（国内友好、免费送 https 域名）为例：
1. 注册 <https://www.cpolar.com/>，下载 Windows 客户端。
2. 配置 authtoken（官网「验证」页给的命令）：
   ```powershell
   cpolar authtoken 你的token
   ```
3. 把本地 8800 暴露成公网 https：
   ```powershell
   cpolar http 8800
   ```
4. 终端会打印一个公网地址，如 `https://abcd1234.r6.cn.cpolar.cn`，**记下它**。
   - 你的**回调 URL** = 该域名 + 回调路径 = `https://abcd1234.r6.cn.cpolar.cn/wechat/kf/callback`
   - ⚠️ 免费版域名**每次重启会变**，变了要回后台改回调 URL；要固定域名可用付费版保留域名。

> 其他可选：frp（你自己有服务器时）、natapp、ngrok（国内可能不稳）。

### 路 B：云服务器 + 域名 + Nginx（更接近生产）
如果你有云 Linux 服务器和域名：
1. 把代码部署到服务器，`python examples/wechat_kf_echo.py`（或 systemd 托管）监听 `127.0.0.1:8800`。
2. Nginx 反代 + Let's Encrypt 证书：
   ```nginx
   server {
       listen 443 ssl;
       server_name kf.yourdomain.com;
       ssl_certificate     /etc/letsencrypt/live/kf.yourdomain.com/fullchain.pem;
       ssl_certificate_key /etc/letsencrypt/live/kf.yourdomain.com/privkey.pem;
       location /wechat/kf/callback {
           proxy_pass http://127.0.0.1:8800;
           proxy_set_header Host $host;
       }
   }
   ```
3. 回调 URL = `https://kf.yourdomain.com/wechat/kf/callback`，域名固定、更稳。

## 4. 回后台填回调配置 → 开通 API → 拿 Secret

1. 回到企业微信后台「微信客服 → API / 回调配置」。
2. 填三项（**必须和 .env 完全一致**）：
   - **URL**：第 3 步的回调 URL（带 `/wechat/kf/callback`）。
   - **Token**：与 `WECHAT_KF_TOKEN` 一致。
   - **EncodingAESKey**：点「随机生成」得到 43 位串 → **同时复制进 `WECHAT_KF_AESKEY` 并重启服务**，保证两边一致。
3. **保存**。此刻企业微信会向你的 URL 发一个 GET 验证请求：
   - 你的服务（必须在线）会解密 echostr 并原样返回 → 后台显示**保存成功 / 验证通过**。
   - 如果失败，见第 6 节排错。
4. 验证通过后，开通成功，**此时去「开发配置」复制真正的 Secret** →
   填回 `WECHAT_KF_SECRET=真Secret` → **重启服务**（`sync_msg`/`send_msg` 这时才能用）。

> 顺序回顾：先跑服务 + 先开穿透 → 后台填回调（验证只用 Token/AESKey）→ 验证通过开通 →
> 拿 Secret → 回填 .env 重启。

## 5. 实测效果

1. 用**任意一个微信**扫第 1.3 步那个客服账号的**接待二维码**，进入客服会话。
2. 发一条文字消息，比如「在吗」。
3. 预期：**几乎立刻收到一模一样的回复「在吗」**（echo 成功）。
4. 同时看本地/服务器**控制台日志**：能看到收到回调、`sync_msg` 拉取、`send_msg` 回复的过程；
   出错也会在日志里打印（`sync_msg 失败` / `send_msg 返回错误` 等）。

✅ 收到回显 = **传输全链路打通**。下一步就可以把 echo 换成 milu 了（见第 7 节）。

## 6. 排错对照表

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 后台保存回调**验证失败** | 服务没在线 / 穿透没开 / URL 写错路径 | 先确认 `https://域名/wechat/kf/callback` 在浏览器能访问到服务（GET 会 403 属正常，能连上即可）|
| 验证失败且日志「URL 验证签名不匹配」 | Token 或 AESKey 两边不一致 | 让 `.env` 与后台三项**逐字符一致**，改完**重启服务** |
| 验证通过但**发消息无回复** | Secret 还是占位 / 没重启 | 填真 Secret 并重启；看日志有没有 `gettoken 失败` |
| 日志 `gettoken 失败 errcode 40013` | corpid 错 | 核对企业 ID |
| 日志 `gettoken 失败 errcode 40001/41002` | Secret 错 / 用错了 Secret | 必须用**微信客服**那个 Secret，不是通讯录/其他应用的 |
| 日志 `send_msg`/`sync_msg` 报 **60020 not allow to access from your ip** | 服务器公网出口 IP 不在可信 IP | 把报错里给出的那个 IP 加进该应用的「**企业可信 IP**」白名单（云服务器才会遇到；穿透到本地一般不触发）|
| 发消息无回复、日志 `send_msg 返回错误 95005`/会话过期 | 超过 **48 小时**会话窗口 / 回复条数超限 | 让用户重新发一条消息触发新会话窗口 |
| 收到图片/语音无回复 | echo 阶段只处理 `text` | 正常；图片/语音类型后续再扩展 |
| 同一条消息**回复了多次** | 企业微信重试（5 秒未回 success）| 我们已用 `msgid` 去重；若仍重复，检查服务是否 5 秒内返回 success（别在请求里同步跑耗时逻辑）|

> 错误码全表见官方：<https://developer.work.weixin.qq.com/document/path/90313>

## 7. 下一步：把 echo 换成 milu / 抽象 Gateway

传输层已通，接 milu **只改一个钩子**，传输代码一行不动：

```python
from milu import LLM
from milu.serving.pool import AgentPool
from milu.agent.events import AgentDone
from milu.channels.wechat_kf import WeChatKfConfig, run_server, create_app

llm = LLM("qwen")                 # 或你的厂商
pool = AgentPool.from_llm(llm)

async def on_text(external_userid: str, text: str) -> str:
    reply = ""
    # 用微信用户 ID 作 user_id：每个微信用户独立会话/记忆/知识库
    async with pool.acquire(user_id=f"wxkf:{external_userid}",
                            session_id=f"wxkf:{external_userid}") as h:
        async for evt in h.agent.run(text):
            if isinstance(evt, AgentDone):
                reply = evt.final_text
    return reply or "（暂时没有回复）"

# 把 on_text 传进去即可（create_app 也支持 on_text 参数）
import uvicorn
uvicorn.run(create_app(WeChatKfConfig.from_env(), on_text=on_text), host="0.0.0.0", port=8800)
```

再往后：把 `WeChatKfClient` 提炼成统一的 `Channel` 接口，新增 Telegram/飞书适配器，
共用一个 `Gateway` + `AgentPool`（见会话里讨论的网关设计）。

### 上生产前必做（echo 阶段有意简化的点）
- **游标 `cursor` 与 `msgid` 去重要持久化**（当前在内存，重启即丢；建议落 `~/.milu` 文件或 Redis）。
- **HTTPS 用固定域名**（别用会变的免费穿透域名）。
- **access_token** 已做缓存，无需每次换。
- 关注 **48 小时回复窗口**与每条消息可回复条数限制。
